## Host / guest path

`ACTIVATE_ABILITY` was already in the protocol's `INTENT_TYPES` and the replay log whitelist; `HostSession.apply` has no per-type whitelist, only the engine `reduce`. `host/abilityHints.test.ts` proves it end to end over the loopback transport: the guest receives the hint in `legalHint`, sends the intent, and both the host state and the guest's sanitised view show the Power (the guest view stays leak-free; `findLeaks` is covered by the existing host tests). The legal hint list stays under `MAX_LEGAL_HINT` (400): `[Add]` hints are a handful per seat.

## Gaps

- Abilities needing targets or a choice are not possible yet (the engine only has target-free abilities). `describeAbility` only has short text for four ops; others say "See card text".
- Tutorial sandbox and the mock game build `legal` with `getUiLegalActions` only where changed here (mock and host); the tutorial sandbox still uses `getLegalActions` (it has no abilities).
- The bot never uses `[Add]` abilities, so Gold the bot owns stays unused.
- Real games only reach Gold/Seals through cards that make them; the e2e uses the `?mock&gold` dev route because standard preset decks do not start with one.
- Line endings: running Prettier over `client/src` rewrote working-copy line endings from CRLF to LF (git normalises them, `git diff --ignore-all-space` shows only the intended files).
