## Design notes

- **No new event types**, so `describeEvent` needed no case (its exhaustive switch still compiles; `EQUIPPED` already existed). The wire protocol and replay allow-list already carry `CHOOSE_TRIGGER_TARGET`; an empty `targets` array is valid input.
- **Sanitize**: every new field (`additionalCosts.repeat`, `CardDef` flags) is public; the leak tests pass unchanged.
- **Bot**: no code change. The empty answer is just another legal `CHOOSE_TRIGGER_TARGET`; tested that `AIController` answers an optional trigger with a legal intent. The host's `legal[0]` fallback (and the tutorial autopilot) takes the first enumerated answer, which is a real target (declining is listed last); for Weaponmaster that means a fallback bot or autopilot equips.
- **Golden hashes** (`reducePurity.test.ts`) did not change: no existing fixture card uses the new triggers, ops or flags.

## Not done (and why)

- **Ambush** (4 single-blocker cards + 13 more): a play permission (Reaction speed, to a battlefield where you have units) changes `canPlayNow`, the location rules in `playCard` and `getLegalActions`; needs its own task.
- **New trigger moments** "When I become exhausted / ready / move", "When you play a card ...", start/end of turn: exhaustion and readying have no single event today (they happen in costs, effects, moves and phases), so a hook per site would be needed. Only ATTACK / DEFEND were added because combat start is one event.
- **Conditional triggers** ("if you control N or fewer runes", "if there is exactly one other unit here", "if I haven't been dealt damage"): need a condition language on `CardTrigger` (only `LEGION` exists).
- **"unit or gear" choices** (Mournful Spirit), **non-targeted "you may"** with costs or discards (Jinx, Chemtech Enforcer, Ekko), additional costs on spells ("exhaust a friendly unit", "return a friendly unit"): need new target kinds / cost choices in `PLAY_CARD`.
- **Keyword grants "this turn"** (`Give a friendly unit [Tank] this turn`, `[Assault]`, `[Ganking]`): no temporary-keyword field on `CardInstance`; every keyword read (`hasKeyword`) is on the card def. Needs a `tempKeywords` list plus a read helper in combat / movement.
- **Repeat leftovers**: "Discard 1" cost (Square Up), several costs (Curtain Call), `[Repeat]` granted by other cards (Syndra, Academy, Temporal Portal), and Repeat spells whose effect is not parseable (Blood Rush needs `[Assault N]` grants; Called Shot; Rocket Barrage "may make different choices").
- Bomb tokens, Buff, Predict, XP/Hunt/Level, Empower, Deploy, Flow remain separate subsystems.

## Risks and follow-ups

1. **Weaponmaster pays automatically** (`autoPlan`): the player picks only the Equipment, not which runes are spent. Affordability is checked when the trigger is put on the Chain and again on resolution; if the pool or runes changed in between the effect fizzles.
2. **Weaponmaster ignores non-resource Equip costs** (same as Equip itself, ASSUMPTIONS "Equip cost"). It does not check that the Equipment is "not already attached to this unit" because the card allows it.
3. **Repeat reuses the same targets.** A different reading (choose again) would need targets for the second pass in `PLAY_CARD`; the current UI and AI would not know about it.
4. **Optional trigger with several optional slots**: the empty answer means "decline everything". Effects that mix an optional and a mandatory choice are not produced by the parser.
5. **Deflect** is still not charged for triggered/activated targets (R41 note), including Disarm and Weaponmaster-free scopes.
6. The ATTACK trigger fires when the combat Showdown starts, after the attacker's units arrived. Units that join later (e.g. via a Reaction play) do not get an "attack" trigger.
