# Browser audit (R17)

Date: 2026-11-05. Branch `feat/foundation`. Read-only audit: no source files were changed and nothing was committed.
App: Vite dev server on http://localhost:5173 (`npm run dev`), card data 1103 cards. Chromium via Playwright (MCP tools and throwaway scripts in the scratchpad, fresh browser context per tutorial run).
Multiplayer (two-browser) flow was out of scope.

Screenshots are in `docs/audit-screenshots/`. Paths below are relative to the repo root.

## Environment caveat (read first)

Other agents were editing `engine/` and `client/` while this audit ran. Vite performed about 36 full page reloads during the run (see the dev log). Each reload resets in-memory tutorial and game state. Runs were therefore retried until they completed, and a few transient failures were traced to reloads, not to the app:

- `SavedGamesScreen` threw "useApp() must be used inside the app provider" after a hot update. It did not reproduce on a fresh load (`docs/audit-screenshots/06-replays-screen.png`). Not counted as an issue.
- Vite logged "conflicting star exports for name 'getLegalActions'" in `engine/src/index.ts` mid-edit. Dev-only, not counted.

## What worked

- Main menu renders and every target responds: Host Game (8 presets, Create room, Import), Join Game (room code field), Play vs AI (Easy and Normal both selectable; both start a game), Tutorial (demo plus 6 lessons with Start / Review), Saved games / Replays ("No saved games yet", Import replay), Settings (Card images and reaction timer toggles). Screens: `01` to `07`.
- Tutorial demo "Meet the board" completes end to end (6 steps, "Lesson complete" screen, no console errors).
- Tutorial lessons 1 (The Turn Structure), 2 (Resources), 3 (Zones and Movement), 4 (Chain) complete with the real engine. The expected refusals appear and match the text: "You do not have priority", "Action illegal during an active Chain (Closed State)", "That unit is exhausted", "lacks Ganking". Rune exhaust and recycle, card play, passes and End turn all work.
- Tutorial lesson 5: damage dialog opens, the engine refuses the Tank-last split with the expected rule text, Auto assign and Confirm work, the result and "What you learned" steps complete. Only the step-4 Next button is blocked (A-01).
- Tutorial lesson 6: steps 1 to 6 work. The last step is blocked by the game-over modal (A-02).
- Solo game (Normal: turn 4 reached with plays and passes; Easy: game starts and mulligan works): mulligan dialog, turn and phase tracker, hand plays, End turn, passes, opponent turns, scoreboard, Resources panel, Chain panel, game log all render. No console errors.
- Dragging a unit from Base to a battlefield works (Grunt drag in lesson 3 starts a Showdown). Click-then-destination moves work.
- Keyboard: Enter / Space plays a focused hand card (verified: "You played Cinder Grunt."). Tab order follows the DOM (lesson guide first, then board). Focus outlines are visible on menu buttons. Escape closes the Concede dialog (targeting-mode Escape not separately tested).
- Deck import: paste and file upload both work. Malformed JSON reports "Invalid JSON: ..." and an unknown card code reports "Unknown card NOPE-2", "Missing legend", "Missing champion". Imported decks show name, legend, event and coverage badge. Rename works (Enter commits). Delete removes the deck. An imported deck starts a solo game (Azir, no errors).
- Responsive: no page-level horizontal overflow on menu, Host, Solo setup or the game screen at 1280, 1024, 768 and 390. The game screen stacks at 390 and every control stays reachable (A-13 is text clipping only).
- Console: no errors during normal menu, deck import, solo or lesson 0 to 4 runs apart from the favicon 404 (A-10) and dev-only HMR messages.
